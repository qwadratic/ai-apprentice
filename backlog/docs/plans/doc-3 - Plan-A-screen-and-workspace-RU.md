> Plan for person A, stream A (screen capture, masks, vision, recording, replay, demo workspace). Russian original. Joint context: `doc-2`; stream B: `doc-4`; task rules: `doc-1`.

ELEVENLABS AI APPRENTICE — ЧЕЛОВЕК A: ЭКРАН И РАБОЧАЯ СРЕДА  
Исправленное распределение: цельные подсистемы, без разделения голоса между людьми.  

ТВОЙ РЕЗУЛЬТАТ  
Готовый модуль наблюдения за экраном: пользователь выбирает окно, закрывает чувствительные данные, система записывает обработанный экран, распознаёт видимые действия и отдаёт наблюдения агенту. Ты также делаешь просмотр записи и тестовую рабочую среду для демонстрации.  
Вся работа с микрофоном, ElevenLabs, вопросами и знаниями — у B.  

1. ПЕРВЫЙ РАБОЧИЙ ВЕРТИКАЛЬНЫЙ СРЕЗ  
• Выбор экрана/окна через getDisplayMedia.  
• Preview исходящего обработанного изображения.  
• Кадр с frameId и timestampMs → vision-модель → структурированное наблюдение.  
• Отдать наблюдение через общий ScreenBridge.  
• Собственный небольшой экран отладки: захват, текущий кадр, последние наблюдения. Можно разрабатывать и проверять без готового агента.  
Готово: B подключается к потоку реальных наблюдений без знания устройства захвата и vision API.  

2. МАСКИРОВАНИЕ И ЗАПИСЬ  
• Ручное закрытие выбранных областей до передачи кадра и до записи видео. Автоматический OCR/PII — только после рабочего основного сценария.  
• Записывать обработанный canvas stream, не сохранять параллельно сырой экран.  
• Маска должна оставаться корректной при изменении окна. При смене геометрии — пауза и повторная проверка; не обещать защиту перемещающегося текста статичным прямоугольником.  
• Пауза останавливает передачу и запись экрана, очищает неотправленные кадры и запрещает выдачу запоздалых результатов.  
• Микрофон ты не подключаешь. Общий off-record у B вызывает паузу твоего модуля и отдельно останавливает голос.  
• Хранить обработанную запись и кадры с таймкодами. Отдать B компонент просмотра записи с переходом к Evidence по времени.  
Готово: скрытый email отсутствует в исходящем кадре и записи; после паузы ничего не отправляется; ссылка на наблюдение открывает правильный момент.  

3. ПОНИМАНИЕ ЭКРАНА  
• Твой vision-адаптер описывает только видимое: открыт клиент, добавлено вложение, введён текст, черновик готов.  
• Причины действий и правила работы не выводить как установленные факты — их выясняет агент B.  
• Начать с одного кадра раз в 1–2 секунды, добавить отсечение одинаковых кадров и ограничение очереди. Измерить реальную задержку.  
• Старые результаты не должны применяться к новому состоянию экрана.  
• Если сущность не распознана — явно unknown. Для демо использовать стабильные синтетические идентификаторы вроде customer_07.  
• Экранный захват не предоставляет глобальные нажатия клавиш чужих приложений. Не строить логику на несуществующих событиях.  
Готово: один и тот же формат описывает действия в таблице, письме и тикете; наблюдения имеют источник и не подменяют догадки фактами.  

4. ДЕМО-СРЕДА — ТОЖЕ ЦЕЛИКОМ ТВОЯ  
Сделать простой sandbox с тремя контекстами одного процесса:  
1) таблица/карточка заказа с адресом и временем доставки;  
2) редактор письма с текстом и изображением-вложением;  
3) тикет с итогом выполненной работы.  

Нужны два разных заказа для одного customer_07, другой клиент и случай с неизвестным клиентом. Все данные вымышленные. B даёт сценарий и ожидаемое поведение агента, ты реализуешь рабочие экраны и reset сценария.  

Сделать явный Preview → Send. На Preview отправлять checkpoint агенту и ждать его результата; при ошибке проверки показывать, что она не завершилась. Решение об отправке остаётся у человека. В демо честно обозначить этот встроенный checkpoint: это не доказательство способности блокировать клики в любом внешнем приложении.  

Готово: эксперт и новичок могут пройти разные случаи; приложение можно быстро вернуть к началу для репетиции. Демо не подсовывает агенту готовое персональное правило.  

5. ЕДИНСТВЕННАЯ ГРАНИЦА МЕЖДУ МОДУЛЯМИ: ScreenBridge v1  
Согласовать с B за первые 20–30 минут. Механизм транспорта выбрать простой; контракт важнее WebSocket против callback.  

Команды:  
start({sessionId, sessionEpochMs}), pause(), resume(), stop().  
resolveEvidence(evidenceId) → {assetRef, startMs, endMs}.  

События:  
ScreenObservation = {  
  id, sessionId, sequence, timestampMs, frameId,  
  kind, facts, entityRef|null, evidenceIds  
}.  
ScreenStatus = {sessionId, state: capturing|paused|stopped|error, reason?}.  
ScreenEvidence = {id, kind: frame|clip, assetRef, startMs, endMs}.  

Дополнение для sandbox:  
ActionCheckpoint = {id, sessionId, timestampMs, observationIds, action: send}.  
Ответ B: {checkpointId, status: clear|warn|unknown, message, evidenceIds}.  
Это всё тот же мост между средой и агентом, а не второй голосовой API.  

Все timestampMs считаются от общего sessionEpochMs. Facts имеет фиксированную согласованную схему. Не расширять типы молча. Поля для голосовых реплик, вопросов и Work Map внутри твоего модуля не нужны.

B владеет всем packages/agent, ElevenLabs, микрофоном и интерфейсами Learn/Review/Teach. Общий app shell и компоновка продукта — у B; ты отдаёшь готовые ScreenPanel и ReplayPanel. Начальный каркас репозитория и корневой lockfile ведёшь ты; новые общие зависимости согласовываете.  

PR: skeleton + ScreenBridge + mocks → capture/privacy → vision/recording/replay → demo-workspace.  
Работать небольшими PR. Не ждать завершения всего блока для первой интеграции.

0,5–2: захват → обработанный кадр → реальное наблюдение; передать B.

8. ПРОВЕРКА ТВОЕГО БЛОКА  
[ ] Реальная картинка превращается в наблюдение со ссылкой на источник.  
[ ] Обработанный preview совпадает с отправляемым и записанным изображением.  
[ ] Пауза прекращает отправку и сбрасывает очередь; старый ответ не просачивается после неё.  
[ ] Replay открывает правильный момент.  
[ ] Неизвестный клиент остаётся неизвестным.  
[ ] Preview проверяется до Send; сбой агента не выглядит как успешная проверка.  
[ ] Новая задача отличается от учебной; reset работает.  

Главный критерий: B может заменить твой модуль mock-потоком, а ты можешь проверять свой модуль без ElevenLabs. При подключении реального ScreenBridge остальная логика не переписывается.
